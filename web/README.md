## 3. 怎么跑起来看效果

**日常开发一条命令就够**（会直接弹出程序自己的窗口）：

```powershell
cd D:\VibeClassAgent
target\release\vca.exe gui
```

改完 `web/` 里的东西，**关掉窗口再跑一次**就能看到新效果 ——
不用编译、不用等后端。实测从起进程到窗口出现约 1 秒。

> F5 刷新被挡掉了（那是浏览器习惯，一个原生程序按 F5 整页重载很怪）。
> 如果你开发时觉得反复开关窗口麻烦，跟我说，我给你加一个
> 「允许 F5」的开发开关。

想用浏览器调试（原生窗口里开不了 DevTools）：

```powershell
target\release\vca.exe gui --no-open --port 4970
# 从日志里取令牌
Select-String -Path data\logs\ui.log -Pattern '\?t='

# 浏览器打开（<TOKEN> 换成上面取到的）
#   http://127.0.0.1:4970/?t=<TOKEN>
```

换端口或指定外部前端目录（默认就用仓库根的 `web/`）：

```powershell
$env:VCA_WEB_DIR = 'D:\somewhere\else\web'   # 可选
target\release\vca.exe gui --port 4971
```

## 4. 三条硬约束

1. **产物必须浏览器能直接跑。**
   想引构建步骤可以（React / Vite / TS 都行），但构建结果必须落在
   `web/` 下、是浏览器直接可执行的形式。
   **部署时我不会跑 `npm build`** —— 目标机器上不装任何运行时，这是项目底线。

2. **`web/index.html` 必须是入口。**
   后端拿"这个文件在不在"判断前端是否存在，改名会静默退回内置旧版本
   （表现为"我改了但没效果"，很难查）。

3. **文案不能硬编码中文。**
   走 `/api/i18n`。新增文案**告诉我**，我加进 `locales/zh-CN.json` 和
   `locales/en-US.json`。你在 JS 里写死中文，英文版就缺一块。

## 5. 几个坑，提前说

- **别依赖浏览器缓存做版本管理。** 所有静态资源带 `Cache-Control: no-store`，
  这是故意的 —— 路径不变、内容会变。
- **URL 里的 `?t=` 令牌不能丢。** `/api/*` 全部要校验（错了回 403），
  静态资源不需要。现有 `api()` 封装已自动带上。
- **`{ok: false}` 也是 HTTP 200。** 必须检查 `ok` 字段，不能只看状态码。
- **`/api/deps` 的 `need_notice` 已经算好了**"这次该不该弹窗"。
  用 `if (st.need_notice)` 就行，别自己判断 `missing.length` ——
  分级策略（必需项每次提示 / 可选项只提示一次）是后端算的。
- **`/api/schedule` 的 `exists: false`** 表示还没建课表，
  该走"引导新建"而不是显示空表格。

## 6. 现在的样子（可以全改）

纯 vanilla JS，无框架无构建。`app.js` 是 **111 KB 单文件** ——
你多半想拆，那就拆，**子目录也支持**（`/sub/mod.js` 实测能取到，
Content-Type 正确）。

现有可能对你有用的约定：

- 主题色在 `style.css` 顶部的 CSS 变量（`--bg-side`、`--accent` 等）；
- 类名用 `.btn.primary`（**不是** `.btn-primary`）；
- `t('key')` 取文案，`api(path, body?)` 发请求。

这些你都可以推翻，只要接口契约不变。
