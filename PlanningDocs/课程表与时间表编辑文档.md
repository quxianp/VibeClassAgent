## 1. 两个核心概念

系统把「作息」和「课程」**严格拆成两个文件**，这是为了适配各校千差万别的作息：

| 概念 | 回答什么问题 | 文件 |
|---|---|---|
| **时间表** | 一天有哪些时段？第几节从几点到几点？课间和午休是哪几段？ | `config/timetable/current.yaml` |
| **课程表** | 某天某节是什么课？谁上？要不要录？ | `config/schedule/current.yaml` |

**为什么要拆开**：
- 同一个作息可以配多份课程表（比如高一、高二作息相同但课程不同）；
- 调作息不用动课程，调课程不用动作息；
- 悬浮窗的显示时机、课后处理的窗口，全部从**时间表的休息段**推导所以时间表填准了，其它都自动。

> **两者组合**后才生成「录制计划」。系统只录制 `record: true` 的课。

## 2. 时间表：作息骨架

### 2.1 位置与格式

```
config/timetable/current.yaml
```

### 2.2 完整示例

```yaml
timetables:
  - id: default
    name: 本校作息              # 显示名，随便取
    is_active: true             # 是否启用（多份时只生效一份）
    source: manual              # manual=手填；classisland=导入（自动填）
    slots:
      # ---- 上课节：type: class，建议带 period ----
      - { period: 1, start: "08:00", end: "08:45", type: class }
      - { period: 2, start: "08:55", end: "09:40", type: class }

      # ---- 休息段：type: break，强烈建议写 name ----
      - { start: "09:40", end: "10:00", type: break, name: 大课间 }
      - { period: 3, start: "10:00", end: "10:45", type: class }
      - { period: 4, start: "10:55", end: "11:40", type: class }
      - { start: "12:10", end: "13:30", type: break, name: 午餐午休 }
      - { period: 5, start: "14:00", end: "14:45", type: class }
      - { period: 6, start: "14:55", end: "15:40", type: class }
      - { start: "17:30", end: "18:30", type: break, name: 晚餐 }
      - { period: 7, start: "19:00", end: "19:40", type: class }
      - { period: 8, start: "20:30", end: "21:30", type: class }
```

### 2.3 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 唯一标识，随便取，如 `default` |
| `name` | 是 | 显示名 |
| `is_active` | 否 | 多份时间表时，只有 `true` 的那份生效 |
| `source` | 否 | `manual` 手填 / `classisland` 导入，仅作标记 |
| `slots` | 是 | 时段列表 |
| `slots[].period` | 否 | 节次号。**上课节建议填**，休息段留空 |
| `slots[].start` | 是 | 开始时间，`HH:mm`（如 `08:00`） |
| `slots[].end` | 是 | 结束时间，`HH:mm`，**必须晚于 start** |
| `slots[].type` | 是 | `class` 上课节 / `break` 休息段 |
| `slots[].name` | 否 | 休息段名称（如「午餐午休」「晚餐」） |

### 2.4 休息段为什么重要 

系统**自动从休息段推导两件事**：

** 处理窗口**（什么时候做课后处理）

只有**时长  15 分钟**的休息段才会成为处理窗口。窗口归属按时段自动判定：

| 休息段开始时间 | 归为 | 处理哪些课 |
|---|---|---|
| 早于 12:00 | `morning` | 上午的课 |
| 12:00  18:00 | `afternoon` | 下午的课 |
| 晚于 18:00 | `evening` | 晚自习的课 |

所以「课间 10 分钟」不会触发处理（时间不够转写），而「午餐午休 80 分钟」会。

** 悬浮窗时机**（下课后 5 分钟显示、上课前 2 分钟关闭）

悬浮窗的关闭时刻取自**下一节课的开始时间**，与休息段无关；但如果没有下一节课，就用兜底时长。

>  **填错时间的后果**：如果时间表里两节课的间隔只有 7 分钟，
> 那么「下课后 5 分钟显示」和「上课前 2 分钟关闭」会算出同一时刻，
> 系统会**跳过这次显示**（避免一闪而过）。这是有意设计，不是 bug。

### 2.5 从零开始写一份时间表的步骤

1. 打开 `config/timetable.example.yaml`，另存为 `config/timetable/current.yaml`；
2. 把 `slots` 按你的作息逐条改写：**先排上课节，再往中间插休息段**；
3. 给每个休息段起个能看懂的名字（方便日志辨认）；
4. 保存后运行校验（见 [12](#12-校验与排错)）。

> 提示：`vca timetable plan` 可以打印推导出的处理窗口，用来核对作息填得对不对。

## 3. 课程表：课程填充

### 3.1 位置与格式

```
config/schedule/current.yaml
```

### 3.2 完整示例

```yaml
# ---------- 教师名单 ----------
teachers:
  - { id: t1, name: 张三, profile: t1 }
  - { id: t2, name: 李四, profile: t2 }

# ---------- 工作日模板 ----------
week_template:
  cycle: "every"                # 整表默认循环：every / odd / even
  entries:
    - { day: Mon, period: 1, start: "08:00", end: "08:45",
        course: 数学, teacherId: t1, record: true, room: "高一(1)班" }
    - { day: Mon, period: 2, start: "08:55", end: "09:40",
        course: 数学, teacherId: t1, record: true, merge: true }
    - { day: Mon, period: 3, start: "10:00", end: "10:45",
        course: 语文, teacherId: t2, record: false }

# ---------- 周末模板 ----------
weekend_template:
  source: new                   # new=新建；inherit=沿用历史
  inherit_from: null            # source=inherit 时填历史周次，如 "2026-38"
  entries:
    - { day: Sat, start: "09:00", end: "10:30",
        course: 竞赛辅导, teacherId: t1, record: true }

# ---------- 临时停课 / 调课 ----------
overrides:
  - { date: "2026-03-20", action: cancel }
  - { date: "2026-03-21", action: move,
      target: { day: Mon, start: "08:00", end: "08:45",
                course: 数学, teacherId: t1, record: true } }
```

### 3.3 教师字段

| 字段 | 说明 |
|---|---|
| `id` | 内部标识，用于与课程条目关联。建议用英文/数字 |
| `name` | 显示名 |
| `profile` | **数据隔离键**。多教师共用一台机器时，每位教师的录像、文档、日志都放在自己的 profile 目录下 |

> 多个教师可以共用一个 `profile`（比如同一台机器同一账号），此时数据会混在一起。

### 3.4 课程条目字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `day` | 是 | `Mon` / `Tue` / `Wed` / `Thu` / `Fri` / `Sat` / `Sun`，也支持 `周一``周日` |
| `start` / `end` | 是 | `HH:mm`，结束必须晚于开始 |
| `course` | 是 | 课程名，会出现在录像文件名与文档标题里 |
| `teacherId` | 是 | 对应 `teachers[].id`。**未填教师时用 `unassigned`** |
| `record` | 否 | **是否录制，默认 false**。这是唯一的开关 |
| `period` | 否 | 节次号，仅作标记 |
| `room` | 否 | 教室，仅作标记 |
| `merge` | 否 | 是否与上一节合并（见 [6](#6-连堂合并)） |
| `cycle` | 否 | 该条目自己的单双周（见 [5](#5-单双周)） |

## 4. 勾选要录制的课

**这是最重要的操作**：导入后的课表里 `record` 全部是 `false`，系统**什么都不会录**，直到你手动打开。

### 方式一：直接改 YAML

```yaml
- { day: Mon, period: 1, start: "08:00", end: "08:45",
    course: 数学, teacherId: t1, record: true }   #  改这里
```

### 方式二：CSV 导入时勾选

CSV 的「是否录制」列填 `是`（兼容 `true` / `1` / `y`）。

### 只录自己的课

多教师共用时，每位老师只把自己上的课设为 `record: true` 即可，
系统会把录像归到该条目的 `teacherId` 对应的 profile。

## 5. 单双周

有两种写法。

### 5.1 整表级（`week_template.cycle`）

```yaml
week_template:
  cycle: "odd"        # 整份课表只在单周生效
```

### 5.2 条目级（`entries[].cycle`）推荐

适用于「同一节，单周上数学、双周上语文」：

```yaml
week_template:
  cycle: "every"
  entries:
    - { day: Wed, start: "08:00", end: "08:45", course: 数学, teacherId: t1, record: true,  cycle: odd }
    - { day: Wed, start: "08:00", end: "08:45", course: 语文, teacherId: t2, record: false, cycle: even }
```

**条目级优先于整表级**。

### 5.3 取值

| 写法 | 含义 |
|---|---|
| `every` / 留空 | 每周都上 |
| `odd` / `单周` / `1` | 只在单周 |
| `even` / `双周` / `2` | 只在双周 |

>  **当前限制**：系统按「当前 ISO 周数是否为奇数」判定单双周
> （`LocalDate::week_key` 给出的周序号）。
> 如果你们学校的单双周与自然周不同步，请在导入后用 `overrides` 校正，
> 或把 `cycle` 都设为 `every` 后手工按周维护。

## 6. 连堂合并

两节连着的同一门课，默认会**合并成一次录制、一份文档**。

自动合并的条件（**四条全满足**）：

1. 课程名相同；
2. 任课教师相同；
3. 后一节开始时间  前一节结束时间；
4. 两节间隔 ** 5 分钟**。

### 手动控制

```yaml
- { day: Mon, start: "08:00", end: "08:45", course: 数学, teacherId: t1, record: true }
- { day: Mon, start: "08:45", end: "09:30", course: 数学, teacherId: t1, record: true, merge: true }
```

### 想拆开怎么办

把其中一节的课程名或教师改得不同（比如「数学(上)」「数学(下)」），或把间隔写大一点（> 5 分钟）。

> 合并后文档标题只出现一次，正文包含两节的内容。

## 7. 临时停课与调课

写在 `overrides` 里，**只影响指定日期**。

### 7.1 整天停课

```yaml
overrides:
  - { date: "2026-03-20", action: cancel }
```

当天的课全部不录。

### 7.2 取消某一节课

```yaml
overrides:
  - { date: "2026-03-20", action: cancel-one,
      target: { course: 数学, teacherId: t1 } }
```

> `target` 里只写 `course` 与 `teacherId` 即可（`day` 可省略）。

### 7.3 加课 / 调课

```yaml
overrides:
  - { date: "2026-03-21", action: add,
      target: { day: Mon, start: "15:00", end: "15:45",
                course: 补课, teacherId: t1, record: true } }
```

`action` 取值：`cancel` / `cancel-one` / `add` / `move`。

## 8. 周末课表

周六、周日的课放在 `weekend_template` 里。系统按当天是星期几自动选择用哪份模板。

### 8.1 新建

```yaml
weekend_template:
  source: new
  entries:
    - { day: Sat, start: "09:00", end: "10:30", course: 竞赛辅导, teacherId: t1, record: true }
```

### 8.2 沿用历史

```yaml
weekend_template:
  source: inherit
  inherit_from: "2026-38"      # 历史周次键（见存档文件名）
  entries: []
```

> **当前限制**：`inherit_from` 字段已建模，但**自动套用逻辑尚未实现**。
> 目前的实用做法是：打开 `config/schedule/archive/schedule_2026-38_001.yaml`，
> 把其中的 `weekend_template.entries` 复制到 `current.yaml`。

## 9. CSV 批量导入

适合从 Excel 维护课表的场景。

### 9.1 生成模板

```bat
scripts\dev.cmd import template csv > 课表模板.csv
```

会得到（UTF-8 BOM，Excel 双击不乱码）：

```csv
星期,节次,开始时间,结束时间,课程,教师,是否录制,教室,周次范围,备注
周一,1,08:00,08:45,课程一,教师甲,是,教室一,,
周一,2,08:55,09:40,课程一,教师甲,否,教室一,,
周二,1,08:00,08:45,课程二,教师乙,是,教室一,,
周六,1,09:00,10:30,课程三,教师甲,是,教室二,,
```

### 9.2 列说明

| 列 | 必填 | 说明 |
|---|---|---|
| 星期 |  | `周一``周日`，或 `Mon``Sun` |
| 节次 | | 数字，可空 |
| 开始时间 |  | `08:00`（也接受 `8:00`、`08:00:00`） |
| 结束时间 |  | 必须晚于开始 |
| 课程 |  | 不能为空 |
| 教师 |  | 空或 `.` `。` `？` 会被识别为「未填写」 |
| 是否录制 | | `是`/`否`、`true`/`false`、`1`/`0`、`y`/`n` |
| 教室 | | 可空 |
| 周次范围 | | 可空；填 `odd` / `even` 表示单双周 |
| 备注 | | 忽略 |

### 9.3 导入

```bat
scripts\dev.cmd import csv D:\课表.csv
```

导入后：
- 课程条目写入**存档**；
- 教师自动去重建立 `teachers` 列表；
- 空教师会归入 `unassigned` 并在报告里列出。

### 9.4 注意事项

- CSV 只导入**课程表**，不含时间表。时间表请用 `import template timetable` 或从 ClassIsland 导入；
- 导入结果是**存档文件**，要生效需把它复制到 `config/schedule/current.yaml`；
- 时间重叠、格式错误会在导入时报错并指出行号。

## 10. 从 ClassIsland 导入

如果学校已用 ClassIsland 排课，可以直接导入，**不用手填**。

### 10.1 找到数据文件

ClassIsland 的数据文件通常是：

```
<ClassIsland程序目录>\data\Profiles\Default.json
```

例如 `D:\ClassIsland_app_windows_x64_selfContained_folder\data\Profiles\Default.json`。

### 10.2 导入

```bat
scripts\dev.cmd import classisland "D:\ClassIsland_app_windows_x64_selfContained_folder\data\Profiles\Default.json"
```

有多个时间表时可指定：

```bat
scripts\dev.cmd import classisland "<路径>" --timetable "高二11"
```

### 10.3 导入器做了什么

| 步骤 | 说明 |
|---|---|
| 读 `TimeLayouts` | 取 `TimeType=0` 的作为上课节、`TimeType=1` 的作为休息段 |
| 读 `ClassPlans` | 展开每个星期（含单双周）的课程格子 |
| 读 `Subjects` | 拿到课程名与教师名 |
| 清洗教师名 | 空 / `.` / `。` / `？` 视为未填写  归入 `unassigned` |
| 拆周末 | 周六周日的条目放进 `weekend_template` |
| 写配置 | `timetable/current.yaml` + `schedule/current.yaml` |
| 写存档 | 同时留存一份带版本号的存档 |

### 10.4 实测示例

用本机真实数据导入的结果：

```
导入报告
  时间表    : 兵团二中高二11上
  课程表份数: 7
  课程条目  : 98
  待补全教师: 早读、体育、自习、政治、通用技术、音乐
```

### 10.5 导入后必做

1. **补全教师**：把 `unassigned` 的条目改成实际教师 id（需要先在 `teachers` 里加人）；
2. **勾选录制**：把所有 `record: false` 改成 `true` 的才是要录的；
3. **核对时间表**：作息是否与学校一致。

>  **安全承诺**：导入器**全程只读**，不写入、不修改、不删除 ClassIsland 的任何文件。

## 11. 存档与防丢失

### 11.1 每次修改都留档

```
config/
  timetable/
    current.yaml                  当前生效
    archive/
      timetable_2026-38_001.yaml  第 1 版
      timetable_2026-38_002.yaml  第 2 版（不覆盖旧的）
  schedule/
    current.yaml
    archive/
      schedule_2026-38_001.yaml
```

- 按 **ISO 周**（`年-周号`）分目录；
- 每次导入/保存生成**新版本**，旧版本永不覆盖；
- **不按学期归档**（按需求约定）；
- 存档**永久保留**，不参与自动清理。

### 11.2 回滚

把想要的存档复制回 `current.yaml` 即可：

```powershell
Copy-Item config\schedule\archive\schedule_2026-38\schedule_2026-38_001.yaml config\schedule\current.yaml -Force
```

### 11.3 备份

存档目前只在本地。建议定期把 `config/` 目录复制到网盘或另一块盘。

> **注意**：`config/profiles/*/secrets.env` 含密钥，备份时请勿上传到不可信位置。

## 12. 校验与排错

### 12.1 常见错误与含义

| 报错 | 原因 | 解决 |
|---|---|---|
| `无法识别的星期：周八` | `day` 写错 | 用 `周一``周日` 或 `Mon``Sun` |
| `结束时间不晚于开始时间` | `end <= start` | 改正时间 |
| `时间格式错误（应为 HH:mm）` | 写成 `8点`、`25:00` | 用 24 小时制 `HH:mm` |
| `课程名为空` | `course` 空 | 补上 |
| `未指定教师` | `teacherId` 空或对不上 | 检查 `teachers` 里是否有该 `id` |
| `时间重叠` | 同一天两条时间交叉 | 调整时间或删掉一条 |
| `CSV 缺少「开始时间」列` | 表头不对 | 用 `import template csv` 生成标准模板 |

### 12.2 自查清单

导入或手改后，逐项确认：

- [ ] 时间表里每个 **上课节** 都写了 `type: class`，且 `period` 不重复；
- [ ] **午休 / 晚餐** 等长休息段写了 `type: break` 且时长  15 分钟；
- [ ] 课程表里每个 `teacherId` 都能在 `teachers` 里找到；
- [ ] 要录的课 `record: true`；
- [ ] 单双周如果不确定，先用 `every`；
- [ ] 时间没有重叠。

### 12.3 看系统怎么理解你的课表


## 13. 字段速查表

### 时间表 `slots[]`

| 字段 | 类型 | 必填 | 取值 |
|---|---|---|---|
| `period` | 整数 | 否 | 1,2,3 |
| `start` | 字符串 | 是 | `HH:mm` |
| `end` | 字符串 | 是 | `HH:mm` |
| `type` | 枚举 | 是 | `class` / `break` |
| `name` | 字符串 | 否 | 任意 |

### 课程表 `entries[]`

| 字段 | 类型 | 必填 | 取值 |
|---|---|---|---|
| `day` | 字符串 | 是 | `Mon``Sun` / `周一``周日` |
| `start` / `end` | 字符串 | 是 | `HH:mm` |
| `course` | 字符串 | 是 | 任意 |
| `teacherId` | 字符串 | 是 | 须存在于 `teachers[].id` |
| `record` | 布尔 | 否 | `true` / `false`（默认 false） |
| `period` | 整数 | 否 | 1,2,3 |
| `room` | 字符串 | 否 | 任意 |
| `merge` | 布尔 | 否 | 默认 false |
| `cycle` | 字符串 | 否 | `every` / `odd` / `even` |

### `overrides[]`

| 字段 | 类型 | 必填 | 取值 |

## 14. 常见问题

**Q：改完文件没生效？**
A：确认改的是 `config/schedule/current.yaml`（不是 `.example`，也不是存档）；然后重启 `vca run`。

**Q：导入后一节课都没录？**
A：因为导入的 `record` 默认是 `false`。这是**有意设计**避免误录。请手动勾选。

**Q：系统会录我不该录的课吗？**
A：不会。只有 `record: true` 的课才会录。

**Q：一天有多节课，会覆盖吗？**
A：不会。每节课生成**独立的作业**（id 含日期+开始时间+课程），各自独立文档、独立清理。

**Q：能同时录两门课吗？**
A：不能。同一时间只支持一路录制；时间重叠的课程会导致未定义行为，请在课表里避免。

**Q：时间表和课程表对不上会怎样？**
A：课程条目自带 `start`/`end`，所以**以课程表为准**；时间表只用于推导休息段（处理窗口）。

**Q：怎么让某一周不录？**
A：用 `overrides` 加 `action: cancel` 指向那一周的日期（需要对每天各写一条）。

**Q：周末课怎么配？**
A：写进 `weekend_template.entries`，系统按当天星期几自动选用。
