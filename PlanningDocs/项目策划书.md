## 1. 项目背景与目标

### 1.1 背景

希沃一体机在部分学校为多教师共用，且不少机型日常使用已感卡顿。系统设计前提：

- 不能成为压垮设备的新负担；
- 不假设存在独显、大内存、空闲 CPU；
- 多教师共用意味着数据、配置、密钥、推送目标都要按人隔离；
- 教师不应理解进程、编码器、API，交互必须极简，靠课表自动驱动；
- 存在周末上课场景，课表需支持周末且可历史沿用或新建；
- 一天有多节课，存在连堂、跨午休、单双周等真实排课形态；
- 各校作息差异大，时间表不能写死，必须支持用户自主配置或导入。

### 1.2 目标

| 目标 | 说明 |
|---|---|
| 课表驱动自动化 | 用户提供课表、时间表、任课老师信息，自主勾选要录的课；系统按此自动录制（含周末） |
| 时间表灵活来源 | 时间表可由用户自主配置，也可从 ClassIsland 等来源导入，或二者混合 |
| 静默运行 | 无弹窗、无气泡；仅一个可关闭的小任务栏图标 |
| 极低占用 | 以卡顿机为基准，见第 7 章 |
| 课后智能处理 | 多个处理窗口自动完成：本地转写  提取要点  关联截图  生成 Word/PDF |
| 自动分发 | 推送渠道用户自选，插件化 |
| 安全清理 | 推送成功后保留 72 小时再删除 |
| 可扩展 | 本地插件市场级接口，全链路可插拔 |
| 易维护 | Rust 维护文档 + CSV/Excel 对接文档 + CLI 自检 |
| 数据不丢 | 课表、时间表全量版本化本地存档 |

### 1.3 非目标

- 不做实时直播、视频剪辑、云端后台；
- 录屏视频不上云；
- 不做强制屏显提示；
- 不做在线插件市场。

### 1.4 两个独立概念：时间表与课程表

系统把「时间表」与「课程表」严格分离，这是支持多校作息差异的关键：

| 概念 | 定义 | 内容 |
|---|---|---|
| 时间表 | 一天的作息骨架 | 第几节从几点到几点、课间与休息段名称（如大课间、午餐午休、晚餐） |
| 课程表 | 时间表上的课程填充 | 某天某节是什么课程、任课教师是谁、是否录制 |

两者组合后才生成录制计划。时间表可被多份课程表复用，课程表也可按单双周拆分。

### 1.5 一天多节课的处理规则

| 场景 | 处理 |
|---|---|
| 一天多节 | 课表按 (day, start, end) 逐条定义，支持任意条数，无上限 |
| 连堂 | 相邻两节同课程同教师时默认合并为一个录制文件、一次后处理、一份文档（可配置关闭） |
| 不连堂 | 默认每节独立录制、独立成 job、独立出文档 |
| 午休切分 | 上午课程在午休窗口处理，下午课程在放学后窗口处理，晚自习课程在晚自习后窗口处理 |
| 同名课程多节 | job 命名带节次与时间，如 数学_第1节_0800、数学_第3节_1000 |
| 同课程跨天 | 文档标题含日期，互不覆盖 |
| 单双周多科目 | 同一节在单周/双周为不同课程，按两份课表分别建模，导入时自动映射 |

### 1.6 处理窗口（三段）

```yaml
processing_windows:
  - { name: 午休,     start: "14:20", end: "15:25", scope: morning,   maxConcurrent: 1 }
  - { name: 放学后,   start: "20:35", end: "21:35", scope: afternoon, maxConcurrent: 1 }
  - { name: 晚自习后, start: "23:35", end: "23:59", scope: evening,   maxConcurrent: 1 }
```

窗口取值参考用户实际作息中的长休息段（午餐午休、晚餐、晚自习后），确保转写不与录制抢资源；默认串行处理，未完成自动顺延到下一窗口。窗口起止由时间表的休息段推导，用户可覆盖。

## 2. 时间表配置与导入（核心）

### 2.1 三种来源，用户自主选择

| 来源 | 适用 | 说明 |
|---|---|---|
| 用户自主配置 | 任何学校 | 在 CLI 或 YAML 中直接定义时间表的各节起止与休息段，最通用 |
| 从 ClassIsland 导入 | 已使用 ClassIsland 的学校 | 只读解析其数据文件，自动提取时间表与课程表 |
| 混合 | 复杂场景 | 从 ClassIsland 导入后再手工微调；或用自主配置的时间表搭配导入的课程表 |

三种方式产出的都是同一份内部模型，后续流程完全一致。

### 2.2 用户自主配置时间表

```yaml
timetables:
  - id: default
    name: 本校作息
    isActive: true
    slots:
      - { period: 1, start: "08:00", end: "08:45", type: class }
      - { period: 2, start: "08:55", end: "09:40", type: class }
      - { period: 3, start: "10:00", end: "10:45", type: class }
      - { period: 4, start: "10:55", end: "11:40", type: class }
      - { period: 5, start: "14:00", end: "14:45", type: class }
      - { start: "12:10", end: "13:30", type: break, name: 午餐午休 }
      - { start: "17:30", end: "18:30", type: break, name: 晚餐 }
```

字段说明：`type` 为 `class`（上课节）或 `break`（休息段）；`break` 段名称可用于推导处理窗口。

### 2.3 从 ClassIsland 导入时间表

实测其 `TimeLayouts` 结构即可直接映射：

| ClassIsland 字段 | 本项目字段 | 转换说明 |
|---|---|---|
| TimeLayouts.*.Layouts[].StartTime | start | 仅取 TimeType=0（上课节） |
| TimeLayouts.*.Layouts[].EndTime | end | 同上 |
| TimeLayouts.*.Layouts[].TimeType | type | 0 映射 class，1 映射 break |
| TimeLayouts.*.Layouts[].BreakName | name | 如午餐午休、晚餐、大课间 |
| TimeLayouts.*.Name | timetables[].name | 时间表名称 |
| TimeLayouts.*.IsActive | isActive | 优先激活项，否则由用户选择 |

### 2.4 只读承诺

程序全程只读解析 ClassIsland 数据文件，不写入、不修改、不删除其任何文件。导入结果仅写入本项目自己的配置目录。

### 2.5 数据零预置规则

程序出厂状态下时间表与课表均为空，不录制任何课；无任何学校名、课程名、教师名、作息时间默认值；首次启动必须经自主配置或导入才能产生录制计划。用户导入的数据属于运行期用户数据，写入用户自己的配置目录，不进入代码、默认配置或交付文档。

### 3.1 功能总览

| 模块 | 插件 ID | 职责 | v1 实现 |
|---|---|---|---|
| 时间表 | 核心 | 作息定义/导入/存档 | 内置 |

| 录制 | recorder | 静默录屏+录音+截图 | ffmpeg（可选 WGC） |
| 转写 | transcriber | 音频转文字 | faster-whisper（本地） |
| 内容提取 | extractor | 文字转要点/通知 | OpenAI 兼容 LLM |
| 截图关联 | screenshot-linker | 时间轴对齐+去重 | pHash + 变化检测 |
| 文档生成 | doc-generator | Word/PDF | python-docx + LibreOffice |
| 推送 | pusher | 发到聊天页 | 企业微信/官方 QQ/第三方（内置） |

| 调度 | 核心 | 时间表与课表触发 | 内置 |
| CLI | 核心 | 交互 | ratatui |
| 插件市场 | 核心 | 本地发现/安装/校验 | 内置 |

### 3.2 模块详述

#### 3.2.0 时间表与课表驱动（核心）

- 时间表来源：用户自主配置或从 ClassIsland 导入，或二者混合；
- 课表来源：手填、CSV/Excel 导入、ClassIsland 导入；
- 用户自主勾选开启录屏的课程；
- 支持工作日模板与周末模板；
- 周末课表两种来源：沿用过往（选历史周次或版本一键套用）或新建；沿用后可局部修改，修改生成新版本，不破坏原历史；
- 生成录制计划，仅勾选课录制；
- 支持按周循环（单双周）、临时调课停课、节假日；
- 时间表与课表均全量版本化存档。

#### 3.2.1 静默录制（recorder）

- 采集前及录制中每 30 秒复评系统负载，高负载时自动降低帧率与码率、拉长截图间隔；
- 极简模式默认开启：720p @ 8fps、CRF30、截图 180s、tiny 模型；
- 硬件编码优先（QSV/NVENC/AMF），失败自动降级 x264；
- 纯本地落盘，按 profile 路由；
- 静默运行：无窗口、无气泡；仅一个小托盘图标，右键菜单提供状态、立即停止录制、打开日志、打开数据目录、退出。

#### 3.2.2 课后处理

1. 转写：faster-whisper（默认 tiny，标准模式 small，强机 medium），完全离线、零调用费；分段转写再合并，控制内存峰值；
2. 提取：LLMProvider 抽象，走 OpenAI 兼容协议，用户自填 baseUrl、apiKey、model；使用 JSON Schema 约束输出；仅发送转写文本，token 少、费用低；
3. 截图关联：依据时间戳对齐，使用 pHash 去重，每节最多 4 张（极简）或 6 张（标准）；
4. 文档生成：同时产出 .docx 与 .pdf，本地保存；极简模式可仅出 Word。

#### 3.2.3 推送（用户自选）

- CLI 命令 push providers list / enable / config；
- 内置渠道：企业微信机器人、官方 QQ 机器人、Server 酱类中转、个人微信第三方协议、第三方 QQ 协议（v1 内置，带明确风险提示，用户自行承担）；
- 每个 profile 独立配置与目标会话；
- 推送回执作为 72 小时倒计时前置条件。

#### 3.2.4 清理（72h，从推送成功起算）

| 环节 | 规则 |
|---|---|
| 起点 | 推送返回明确成功的时刻 t0 |
| 倒计时 | expireAt = t0 + 72 小时 |
| 保留期 | 72 小时内可 CLI 恢复或标记重要 |
| 删除 | 到期且二次校验推送成功，物理删除 |
| 失败 | 推送未成功则不启动倒计时、不删除，重试并告警 |
| 空间不足 | 只清理已成功推送且接近到期的文件，绝不删未推送的 |
| 标记重要 | 进入永久保留区，不参与自动清理 |

## 4. 系统架构设计

### 4.1 整体分层

```
交互层：CLI(ratatui)  配置  日志  托盘小图标
调度层：时间表与课表驱动  时段触发  任务队列  多 profile  重试
插件层：recorder / transcriber / extractor / linker / doc / pusher / cleaner
核心服务：事件总线  配置  文件  存档  密钥  日志  状态机
平台层：Windows 采集  进程  计划任务  硬件探测  会话
```

### 4.2 插件机制（本地市场级）

插件包结构：

```
my-plugin/
  manifest.toml
  bin/
  README.md
  LICENSE
  checksums.json
  signature.sig        （可选）
```

manifest 示例：

```toml
[plugin]
id = "pusher.wechat.personal"
name = "个人微信推送（第三方协议）"
version = "1.0.0"
api_version = "1"
kind = "pusher"
risk_note = "使用第三方协议存在账号风险，请自行评估"

[runtime]
type = "process"
entry = "bin/pusher-wechat-personal.exe"
timeout_sec = 30
restart = "on-failure"

[permissions]
network = ["https://example.com"]
filesystem = ["read:docs/**", "write:logs/**"]

[config]
token = { type = "string", secret = true, required = true }
target = { type = "string", required = true }
```

运行模式：process（默认，JSON-RPC over stdio）、cdylib、wasm。

统一接口方法：init、run、cleanup、health_check、describe。

本地市场命令：plugin list / install / remove / enable / disable / info / doctor；安装时校验 checksum、接口版本、权限声明，并向用户展示权限与风险求确认；预留 marketplace.remoteUrl 配置项（v1 为空）。

### 4.3 接口稳定性

api_version 大版本不匹配拒绝加载，小版本向后兼容；describe() 返回能力与 Schema；弃用策略为先标记 deprecated，至少保留一个大版本。

### 4.4 通信与数据流

进程内采用事件总线（发布订阅）；跨进程采用 JSON-RPC over stdio 或命名管道；中间产物落盘 jobs/{jobId}/，支持断点续跑。

```
时间表（自主配置或导入） + 课表（手填/CSV/导入）
         生成录制计划
         上课时段  recorder  raw/(profile 私有)
处理窗口  transcriber  extractor  linker  doc-generator(Word+PDF)
         pusher(用户所选)  成功回执(t0)  cleaner(72h)
```

### 4.5 托盘图标

一个小图标，无气泡、无弹窗。右键菜单：状态、立即停止录制、打开日志、打开数据目录、退出。录制中角标默认关闭。

### 4.6 多教师共用设计

| 维度 | 方案 |
|---|---|
| 身份识别 | 默认 Windows 登录账户；同账户多人使用时用 CLI --profile 显式切换 |
| 数据隔离 | data/profiles/{profile}/... 各自独立 |
| 配置隔离 | 每个 profile 独立 settings.yaml 与 secrets.env |
| 推送隔离 | 每个 profile 独立渠道与目标会话 |
| 课表归属 | 课表条目绑定任课老师，自动路由到其 profile |
| 时间表共享 | 时间表为全校共用，可按 profile 覆盖 |
| 调度冲突 | 同时段冲突以先到先占加 CLI 提示处理 |
| 权限 | 进程以登录用户身份运行；profile 目录 ACL 限本人 |
| 隐私 | 默认视图中看不到他人文档与日志 |

## 5. 技术选型

### 5.1 语言裁决：Rust 宿主 + Python 子进程

| 维度 | C++ | Rust | 权重 |
|---|---|---|---|
| 运行时资源（CPU/内存） | 五星 | 五星 | 高（打平） |
| 二进制体积 | 四星 | 五星 | 中 |
| 内存安全 | 二星 | 五星 | 极高 |
| 并发安全 | 二星 | 五星 | 极高 |
| 错误处理 | 二星 | 五星 | 高 |
| 依赖与构建 | 二星 | 五星 | 极高 |
| 插件 ABI 稳定性 | 不稳 | 不稳 | 两者都用进程隔离规避 |
| Windows 采集生态 | 五星 | 四星 | 中 |
| 长期维护成本 | 高 | 低 | 决定性 |

裁决：宿主选 Rust。理由是「最省资源」这一条 C++ 与 Rust 打平，不构成选 C++ 的决定性理由；而长期维护性 Rust 显著优于 C++（编译期消除内存与并发错误，Cargo 统一依赖与构建）。用户已有 C++ 算法竞赛基础，迁移 Rust 成本低。插件 ABI 问题用进程隔离（JSON-RPC）解决，任何语言均可写插件。Python 仅用于重算法部分，按需拉起、用完释放，规避其内存大、启动慢的缺点。

推荐组合：

| 层 | 语言 | 理由 |
|---|---|---|
| 宿主、调度、CLI、插件管理、录制编排 | Rust | 体积小、内存低、并发安全、Cargo 好维护 |
| 录制引擎 | Rust + ffmpeg 子进程 | 复用成熟编码 |
| 转写 | Python（faster-whisper），按需子进程 | 生态无可替代 |
| 文档生成 | Python（python-docx） | 模板、图片、表格方便 |
| PDF 转换 | LibreOffice headless | 版式稳定、中文字体可控 |
| 插件 | 任意语言（进程 + JSON-RPC） | 生态最开放 |

### 5.2 录屏录音

默认 ffmpeg（兼容性好、可控），可选 Windows Graphics Capture API 插件（启动更快）；硬编优先，失败降级 x264；低配默认 10fps，极简 8fps。

### 5.3 语音转写（纯本地、零费用）

首选 faster-whisper（CTranslate2 加速，较原版快数倍、内存更低），备选 whisper.cpp（纯 C++、CPU 友好、体积小，适合极低配机）；模型 tiny / small / medium，默认 tiny（极简）或 small（标准）。完全离线，零调用费，录屏不上云。

### 5.4 文档生成：Word + PDF

| 目标 | 方案 | 理由 |
|---|---|---|
| Word (.docx) | python-docx | 成熟，可控样式、图片、表格 |
| PDF | LibreOffice headless 转 PDF | 版式稳定，中文字体可控 |
| 备选 PDF | Pandoc | 若无 LibreOffice 则降级 |
| 图片 | 压缩为 JPEG 后嵌入 | 控制文档体积 |

交付方式：同一份内容同时产出 .docx 与 .pdf，均本地保存。

### 5.5 推送（插件化，用户自选）

| 渠道 | 实现 | 说明 |
|---|---|---|
| 企业微信机器人 | Webhook | 官方支持，稳定 |
| 官方 QQ 机器人 | 开放平台 | 合规，需审核 |
| Server 酱 / PushPlus | HTTP | 接入简单，有额度限制 |
| 个人微信 / 第三方 QQ 协议 | 独立插件 | v1 内置，带风险提示 |

凭据一律走环境变量或 secrets.env，不入库；每 profile 独立配置。

### 5.6 CLI 框架

Rust + ratatui + clap，与宿主同语言以减少技术栈。命令：config、timetable、schedule、record、task、plugin、market、log、doctor、profile。

### 5.7 第三方库选型原则（稳定性优先）

1. 优先选用维护活跃、社区成熟、有长期 release 记录的库；
2. 关键路径（录制、转写、文档、推送）保留可降级实现，避免单点依赖；
3. 依赖需锁定版本并记录于依赖与许可清单（附录 A10）；
4. 安装与分发包优先选择纯本地、无网络依赖的形态。

## 6. 关键流程时序

### 6.1 正常流程

```
[启动] 载入时间表（自主配置或导入）与课表（含历史存档）
       生成当日录制计划（多节，仅勾选课）

[08:00] 第 1 节命中  recorder 静默开始（绑定任课老师 profile）
[08:45] 第 1 节结束  job #1 = RECORDED
[08:55] 第 2 节命中（连堂，merge） 并入同一 job
[09:40] 结束  RECORDED
[10:55] 第 4 节命中  ...  RECORDED

[14:20] 处理窗口「午休」(scope=morning)
         对上午所有 job：transcriber  extractor  linker  doc-generator
         pusher(用户所选)  PUSHED（各自记 t0）
         cleaner：expireAt = t0 + 72h

[15:30] 下午课开始  recorder ...  RECORDED
[20:35] 处理窗口「放学后」(scope=afternoon)  同上流程
[23:35] 处理窗口「晚自习后」(scope=evening)  同上流程

[t0+72h] 各 job 分别到期，二次校验推送成功  物理删除
```

### 6.2 异常与中断处理

| 异常 | 处理 |
|---|---|
| 机器卡顿或负载高 | 自适应降帧率与码率，必要时暂停截图采样，极端情况告警但不中断录制 |
| 录制中崩溃 | 启动自检修复临时文件，失败则标记损坏但保留 |
| 模型 API 超时或限流 | 指数退避重试，耗尽后保留中间产物待手动重跑 |
| 推送失败 | 不启动 72 小时倒计时、不删除，重试并告警 |
| 断电或关机 | 启动扫描未完成任务，进入补跑队列 |
| 调课、停课、节假日 | 覆盖规则处理，CLI 提示 |
| 时间表导入失败 | 保留原有时间表不变，回滚到上一版本，提示用户自主配置 |
| 磁盘空间不足 | 只清理已推送且接近到期的文件，绝不删未推送的 |
| 系统时间跳变 | 使用单调时钟计时，避免 72 小时计算错乱 |

## 7. 性能与资源占用目标（卡顿机基准，极简默认）

### 7.1 指标

| 指标 | 目标值 |
|---|---|
| 待机 CPU | 低于 0.3%（单核） |
| 录制中 CPU | 低于 3%（硬编）或低于 8%（软编） |
| 内存常驻（录制中） | 低于 100 MB |
| 转写内存峰值 | tiny 低于 300MB；small 低于 600MB |
| GPU 占用 | 硬编低于 8%；软编接近 0 |
| 默认录制参数（极简） | 720p @ 8fps，CRF30，AAC 64kbps 单声道 |
| 单节录像体积 | 约 60 至 180 MB / 45min |
| 截图 | 每 180 秒一张，去重后每节不超过 4 张，JPEG 质量 70 |
| 文档体积 | 小于 5 MB |
| 启动延迟 | 小于 2 秒 |
| 停止落盘 | 小于 3 秒 |

### 7.2 降占用手段

8fps 加高 CRF；硬编优先，失败降级并同步降分辨率；负载侦测自动降档；转写严格错峰处理窗口；截图去重压缩；插件按需加载；Python 子进程用完即退；磁盘缓冲加分片写减少小写。

### 7.3 两档预设

| 项 | 极简（默认开启） | 标准 |
|---|---|---|
| 分辨率与帧率 | 720p @ 8fps | 1080p @ 10fps |
| CRF | 30 | 28 |
| 截图间隔 | 180 秒 | 90 秒 |
| 转写模型 | tiny | small |
| 文档图片 | 不超过 4 张，质量 70 | 不超过 6 张，质量 80 |
| 文档格式 | 仅 Word | Word + PDF |
| 转写线程 | min(2, N-1) | N-1 |

## 8. 数据与文件管理

### 8.1 目录结构

```
%ProgramData%\ClassRecorder\
   config\
      global.yaml
      timetable\
         current.yaml
         archive\{yyyy-ww}\*.yaml      时间表全量版本化
      schedule\
         current.yaml
         archive\{yyyy-ww}\*.yaml      课表全量版本化
      profiles\{profile}\settings.yaml
                           \{profile}\secrets.env    禁止入库
   data\profiles\{profile}\
      jobs\ raw\ audio\ screenshots\ transcript\ docs\ trash\ logs\
   plugins\
```

### 8.2 命名规则

```
录像：{yyyyMMdd}_{HHmm}-{HHmm}_{课程}_{profile}.mp4
文档：课堂纪要_{yyyyMMdd}_{课程}_{profile}.docx / .pdf
删除计划：{jobId}.deleteplan.json   expireAt = pushSuccessTime + 72h
时间表存档：timetable_{yyyy-ww}_{v}.yaml
课表存档：schedule_{yyyy-ww}_{v}.yaml
```

### 8.3 生命周期

| 类型 | 策略 |
|---|---|
| 原始录像 | 推送成功后设置 expireAt，到期删除；期间可恢复或标重要 |
| 音频 | 转写与推送成功后删除（可配置保留） |
| 转写文本 | 长期保留（体积小） |
| 截图原图 | 文档生成后压缩保留，原图可选删除 |
| Word / PDF | 长期保留（可配置上限） |
| 日志 | 滚动保留 30 天 |
| 时间表与课表存档 | 永久保留、版本化、本地、不自动删除，不按学期归档 |

### 8.4 隐私与安全

1. 密钥一律走环境变量或 secrets.env，绝不入库；
2. 全局 .gitignore 覆盖 .env、*.pem、*.key、*credentials*、*secrets*、*_rsa；
3. 检查 git config，禁止 URL 内嵌 token；
4. 提供 pre-commit 钩子扫描敏感串；
5. 录屏与音频不上云；仅转写文本可发送给用户自填的 LLM；
6. 日志脱敏，Key 只打印前后各 4 位；
7. profile 目录 ACL 限本人。

### 8.5 时间表与课表存档、防丢失

| 需求 | 方案 |
|---|---|
| 全量版本化 | 每次保存生成新版本文件，旧版本不覆盖 |
| 历史沿用 | timetable list-archive 与 schedule list-archive 查看，apply 沿用 |
| 归档粒度 | 按周（yyyy-ww）本地存档，不按学期归档 |
| 防丢失 | 本地多版本留底；可选导出备份 zip；可选备份到用户指定本地目录（仅文本） |
| 一致性 | current.yaml 由版本文件生成，撤销即回滚 |
| 审计 | 记录每次变更的时间、操作者、差异 |

### 9.4 周末课表沿用规则

用户可选择沿用过往（指定历史周次或版本一键套用）或新建；沿用后可局部修改，修改生成新版本，不破坏原历史；所有版本自动存档。

### 9.5 配置方式

CLI 交互（带 Schema 校验）、直接编辑 YAML、环境变量与 secrets.env、首次向导（不推荐渠道，仅给 help 页入口）。

### 9.6 时间表与课表导入向导

1. 选择来源：自主配置时间表 / 从 ClassIsland 导入 / 混合；
2. 若导入，选择数据文件；
3. 选择时间表（若有多个则列出，优先 IsActive）；也可选择自主配置并跳过；
4. 学期对齐：输入本学期第 1 周的周一日期，并选择该周为单周还是双周（用户导入后自主选择）；
5. 教师清洗：列出教师名为空或为占位符的科目，请用户补全（可留空跳过）；
6. 课程勾选：默认全部不录，用户自主勾选需要录制的课，支持按天或按课程批量勾选；
7. 确认并存档：生成新版本 timetable.yaml 与 schedule.yaml，原历史版本保留。

### D3 零预置规则

程序在未配置、未导入任何用户数据的出厂状态下：时间表与课表均为空，不录制任何课；无任何学校名、课程名、教师名、作息时间默认值；首次启动必须经自主配置或导入才能产生录制计划。

禁止出现在代码、默认配置、示例模板、交付文档中的内容：真实学校名、真实教师姓名、真实课表内容、任何基于单一学校数据硬编码的时间表。

允许存在的示例数据：通用虚构值（课程一、课程二、教师甲、教师乙、教室一），以及明确标注为格式示例的 CSV 与 Excel 模板。

### D4 导入器安全承诺

全程只读，不写、不改、不删 ClassIsland 任何文件；导入结果只写入本项目自己的配置目录。
