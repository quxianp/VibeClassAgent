## 二、本次生成方式与稳定性说明

### 环境实测结果
- Python 3.14 可用，Node.js 可用；
- 网络可达，pip 可下载 python-docx 1.2.0；
- 但 pip 解包阶段出现 Errno 13（对临时目录 .metadata 的写入被沙箱拒绝），多次调整
  --target / TMP / TEMP 后仍无法完成安装；
- 环境未安装 LibreOffice 或 Pandoc，且 pip 安装路径不可用。

### 本次采用方案：零依赖 OOXML 直接构造
.docx 本质是一个 zip 包，内含 document.xml、styles.xml、[Content_Types].xml 及关系文件。
本次由 Python 标准库 zipfile 与 xml 直接构造上述部件，未依赖任何第三方库。

稳定性依据：
1. 仅使用 Python 标准库（zipfile、re、html、xml），无外部依赖，不受网络与权限影响；
2. OOXML 为 ECMA-376 国际标准，结构稳定，Word 2007 及以上原生兼容；
3. 生成后已做完整性校验：zip 无损、5 个 XML 部件全部可解析、21 张表格与 794 段落结构正确；
4. 已验证中文字体（微软雅黑）与关键内容完整，无乱码。

### 关于「第三方库需确保稳定性」的落实
本备注已作为项目正式选型原则纳入策划书第 5 章，落实为三条约束：
1. 优先选用维护活跃、社区成熟、有长期 release 记录的库；
2. 关键路径（录制、转写、文档、推送）保留可降级实现，避免单点依赖；
3. 依赖需锁定版本并记录于依赖与许可清单（策划书附录 A10）。

本次文档生成即体现了第 2 条：在第三方库不可用时，零依赖降级路径可正常产出可用文档。

### 正式开发时的推荐路径（网络与权限正常时）
- Word：python-docx（MIT 许可，维护活跃，PyPI 下载量高）；
- PDF：LibreOffice headless（成熟稳定）或 Pandoc（备选）；
- 二者均已写入策划书 5.4 节。
